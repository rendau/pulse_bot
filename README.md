# pulse_bot

Telegram-бот для разговора об инфраструктуре поверх MCP-сервера pulse.
Что строим и принятые решения — [docs/bot-spec.md](docs/bot-spec.md).

### Сборка и запуск

```
make build
go run ./cmd/.
```

Переменные окружения — `internal/config/config.go`, пример — `.env.example`.

### Бот в группе

1. В @BotFather: `/setprivacy` → бот → **Disable**. С включённым режимом приватности Telegram
   не присылает боту упоминания `@бот` — доходят только команды `/cmd@бот` и ответы на его
   сообщения. Остальную переписку группы бот пропускает сам.
2. Добавить бота в группу. Если бот уже был в группе до смены режима — удалить и добавить
   заново: новый режим действует только после повторного добавления.
3. Дописать id группы (с минусом) в `TELEGRAM_ALLOWED_CHAT_IDS` в kusec. Id бот пришлёт сам:
   как только его добавили в группу, админы (`TELEGRAM_ADMIN_USERS`) получают в личный чат её
   название, id, кто добавил и есть ли id в списке (то же — строкой в логе). Админ должен хоть
   раз написать боту сам (`/start`): первым бот написать человеку не может. Сообщения из
   неразрешённых групп бот отбрасывает молча.

Проверка: `/help@<бот>` в группе. Бот молчит — не тот id: группа могла стать супергруппой,
тогда id меняется на вид `-100…` — бот напишет админам новый и прежний id; отвечает на команду,
но не на `@бот` — режим приватности не выключен.

### Блокировка атакующих адресов

Под уведомлением об атаке из интернета (вид `security`, приходит по отдельной подписке) — второй
ряд кнопок: «⛔ Блок 24 ч», «⛔ Блок 7 дней», «Не блокировать». Нажимать могут только админы бота
(`TELEGRAM_ADMIN_USERS`; в группе кнопки видят все, остальным бот отвечает отказом). Блокирует
адрес в ruto pulse_agent (`POST /v1/notifications/{id}/block`), у бота ключа ruto нет. Чтобы
кнопки работали, бот должен быть в `BLOCK_CLIENTS` агента; иначе бот ответит «Боту не разрешено
блокировать». После решения ряд блокировки исчезает, в чат — кто и что решил; если ruto отказал,
кнопки остаются, а в чат — текст отказа.
